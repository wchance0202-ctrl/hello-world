# 企业查询有用性打分标准

> 版本：v1.0 ・ 适用对象：标注员、质检员、评测负责人
> 用途：评估系统（搜索引擎、企业信息平台、智能问答 / 大模型）在回答"企业查询"时，结果对用户是否**真正有用**。

---

## 1. 适用范围

### 1.1 什么是"企业查询"

用户以获取**企业相关信息**为目的发起的查询，包括但不限于：

| 查询类型 | 说明 | 示例 |
|---|---|---|
| A. 企业定位 | 查找某一家具体企业 | "华为技术有限公司"、"深圳腾讯" |
| B. 属性查询 | 查询企业的某项具体信息 | "比亚迪法人是谁"、"小米注册资本多少" |
| C. 风险查询 | 司法、经营异常、行政处罚、失信等 | "某某公司有没有被执行"、"某公司是否失信" |
| D. 关系查询 | 股东、实控人、对外投资、分支机构、关联企业 | "蚂蚁集团的实际控制人"、"某公司投资了哪些企业" |
| E. 经营与财务 | 营收、融资、年报、招投标、知识产权、招聘 | "宁德时代2025年营收"、"某公司专利数量" |
| F. 列表 / 筛选 | 按条件找一批企业 | "杭州的新能源汽车企业"、"注册资本过亿的苏州医药公司" |
| G. 比较 / 综合判断 | 多企业对比、尽调、合作评估 | "对比A公司和B公司的风险"、"这家公司靠谱吗" |

### 1.2 打分对象

对**一条查询 + 一条系统返回结果**（一个回答或一组搜索结果）整体打分。若评估搜索结果列表，默认看**首屏 / 前 3 条**，并在备注里注明。

---

## 2. 总体原则

1. **以用户意图为中心**：分数反映"用户拿到这个结果后，需求被满足的程度"，而不是结果写得多漂亮、多长。
2. **准确先于完整**：一条错误的信息比缺一条信息危害更大。企业信息常被用于合作、投资、放贷等决策，**错误信息按"有害"处理**。
3. **实体对了才谈其他**：企业同名、简称、曾用名非常常见，先确认结果指向的是用户要找的那家企业。
4. **时效敏感**：企业状态（存续 / 注销 / 吊销）、法人、股东、风险信息会变化，过时信息视同不准确。
5. **独立判断**：每条样本独立打分，不受上一条样本或其他系统结果影响。

---

## 3. 分数等级定义（0–3 分）

| 分数 | 等级 | 定义 | 用户感受 |
|:---:|---|---|---|
| **3** | 有用 | 准确命中目标企业，完整回答核心需求及主要隐含需求；信息准确、时效清楚；用户**无需再查**。允许存在不影响使用的小瑕疵（如排版略乱、未标注数据日期但数据实际是新的），需在备注中注明 | "就是这个，够用了" |
| **2** | 部分有用 | 只满足部分需求：缺少某项关键信息，或信息需要用户**额外查证**才敢用；或在多个候选企业中没有帮用户消歧 | "有点用，但还得自己再查" |
| **1** | 基本无用 | 与查询相关但**没回答核心问题**；信息严重过时；只给出泛泛介绍或只给出"请去某网站查询"；关键字段有错误 | "跟我问的关系不大" |
| **0** | 无用 / 有害 | 答非所问；**企业实体错误**（把 A 公司的信息安到 B 公司）；捏造信息；关键结论错误可能误导决策（如把已注销企业说成正常经营） | "完全没用，甚至会坑我" |

> 只打整数分。在两档之间确实难以取舍时，**就低不就高**，并在备注中写明犹豫的原因，便于质检和后续修订标准。

---

## 4. 打分流程（五步法）

```
① 理解意图 → ② 一票否决检查 → ③ 分维度评估 → ④ 给出基础分 → ⑤ 应用封顶规则，得到最终分
```

### 第 ① 步：理解查询意图

明确三件事并写进标注备注：

- **目标实体**：用户要查的是哪家（哪些）企业？查询是否存在歧义（同名、简称、地区不明）？
- **核心需求**：用户最想知道的那一项信息是什么？
- **隐含需求**：用户没说但大概率需要的信息。例如：
  - 查"某公司电话" → 隐含需要确认是官方 / 工商登记电话；
  - 查"某公司靠谱吗" → 隐含需要经营状态、成立年限、风险信息、涉诉情况；
  - 查"某公司法人" → 隐含需要知道是否近期发生过变更。

### 第 ② 步：一票否决检查（命中任一项，直接 0 分）

| 编号 | 否决项 |
|---|---|
| V1 | **实体错误**：返回的是另一家企业的信息，且未做任何提示（如同名不同地区、简称指向错误） |
| V2 | **捏造信息**：编造不存在的企业、股东、数字、判决、新闻等 |
| V3 | **完全答非所问**：与企业查询意图无关 |
| V4 | **关键结论颠倒**：如把"已注销 / 吊销"说成"存续"，把"失信被执行人"说成"无风险"，可能直接导致错误决策 |
| V5 | **违规内容**：泄露自然人隐私（个人身份证号、私人手机号、家庭住址等非公示信息）或含违法违规内容 |

### 第 ③ 步：分维度评估

对以下 7 个维度逐项判断，作为给基础分的依据（每项记"好 / 一般 / 差"即可，若项目需要量化，见第 7 节）。

| 维度 | 评估要点 | 常见扣分情形 |
|---|---|---|
| **D1 实体准确性** | 是否命中正确企业；歧义查询是否列出候选并给出区分信息（地区、成立时间、信用代码） | 多个同名企业随便选一个；把分公司当总公司；把曾用名企业当成另一家 |
| **D2 意图满足度** | 是否直接回答了核心需求 | 问法人却大段介绍公司历史；核心答案埋在长文末尾 |
| **D3 信息准确性** | 关键字段是否与权威来源一致 | 注册资本单位错（万元/元）、币种错、法人姓名错、成立日期错 |
| **D4 完整性** | 核心需求与主要隐含需求是否覆盖；列表类是否覆盖主要结果 | 风险查询只列诉讼不提失信 / 被执行；列表只给 2 家 |
| **D5 时效性** | 信息是否为最新，是否标注数据时间 | 法人已变更仍显示旧法人；引用 3 年前的融资信息当作现状 |
| **D6 来源可信度** | 是否基于权威来源（国家企业信用信息公示系统、裁判文书网、执行信息公开网、交易所公告、企业官网等），是否可追溯 | 只有来源不明的自媒体内容；无法核实的"据说" |
| **D7 表达与可用性** | 结构清晰、重点突出、数字带单位、术语准确；必要时给出风险提示和后续查询指引 | 堆砌原始数据无总结；表格错乱；中英文混乱 |

**维度优先级**：D1 > D3 > D2 > D5 > D4 > D6 > D7。前三项出问题对分数影响最大。

### 第 ④ 步：给出基础分

根据维度评估结果，对照第 3 节的等级定义给出基础分。参考映射：

| 维度评估情况 | 建议基础分 |
|---|---|
| D1–D3 "好"，D4、D5 无"差"，其余至多有 1–2 项"一般" | 3 |
| D1 "好"，但 D2/D4/D5 中有"差"，或 D3 中次要字段有误 | 2 |
| D2 "差"（没回答核心问题），或 D3 中关键字段有误 | 1 |
| 命中第 ② 步否决项 | 0 |

### 第 ⑤ 步：应用封顶规则

基础分不得高于以下封顶值（取所有命中规则中的**最低**封顶值）：

| 编号 | 情形 | 封顶 |
|---|---|:---:|
| C1 | 关键字段（企业全称、统一社会信用代码、法定代表人、注册资本、经营状态、成立日期）中**任一项错误** | 1 |
| C2 | 次要字段（地址、电话、经营范围、参保人数等）有错误 | 2 |
| C3 | 歧义查询（同名 / 简称）未消歧，直接默认一家且未提示 | 2 |
| C4 | 企业处于注销、吊销、停业、经营异常等非正常状态，但结果**未提示** | 2 |
| C5 | 时效敏感信息（法人、股东、风险、经营状态）明显过时且未标注时间 | 2 |
| C6 | 公开可查的信息却拒绝回答，或只回复"请自行到某网站查询" | 1 |
| C7 | 风险 / 尽调类查询未给出任何风险信息检索结论（包括"未发现风险"的明确结论） | 2 |
| C8 | 列表 / 筛选类结果中有明显不符合筛选条件的企业，占比 ≥ 30% | 2 |
| C9 | 涉及投资、借贷、合作等决策建议时，给出绝对化结论（"一定靠谱""完全没风险"）且无依据 | 2 |

## 5. 分查询类型的关键要求

不同类型查询，"什么算有用"侧重点不同。打 **3 分**需满足对应类型的全部"必备要素"。

| 类型 | 必备要素（缺一不能给 3 分） | 加分要素 | 典型低分原因 |
|---|---|---|---|
| A. 企业定位 | 企业全称、统一社会信用代码、经营状态、法定代表人、成立日期、注册地 | 官网、简介、所属行业、规模 | 同名企业混淆；只给官网链接无基本信息 |
| B. 属性查询 | 准确回答被问字段；字段有时间属性时注明时间 | 变更历史（如法人变更记录） | 答非所问、单位错误、旧数据 |
| C. 风险查询 | 覆盖主要风险维度（司法诉讼、被执行 / 失信、经营异常、行政处罚、股权冻结 / 出质）并给出结论；无风险时明确说明"截至某日未查到" | 风险等级概括、案件金额、时间线 | 只覆盖一两个维度；把原告案件当被告风险 |
| D. 关系查询 | 关系方准确、持股比例 / 关系类型明确；实控人类问题说明穿透依据 | 股权结构图、关联风险 | 持股比例错误；混淆直接 / 间接持股 |
| E. 经营与财务 | 数据准确、口径明确（年份、币种、单位、合并 / 母公司）、来源可追溯 | 同比变化、行业对比 | 年份口径混乱；非上市公司数据来源不明 |
| F. 列表 / 筛选 | 结果符合全部筛选条件；数量合理；每条带关键识别信息 | 排序合理、提供筛选维度说明、总数说明 | 条件不符；数量过少；重复企业 |
| G. 比较 / 综合判断 | 比较维度一致、数据同口径；结论有依据；给出风险提示 | 结构化对比表、建议后续核查项 | 只罗列不比较；结论无依据或过于绝对 |

### 5.1 时效性参考标准

| 信息类别 | 建议时效 | 说明 |
|---|---|---|
| 经营状态、法人、股东、注册资本 | 与权威登记信息一致 | 存在变更却显示旧值即视为过时 |
| 司法风险、被执行、失信 | 近 1 个月内更新 | 风险类信息变化快 |
| 财务数据 | 最近一期已披露数据 | 应注明报告期 |
| 新闻舆情、融资 | 依查询意图，"最新"类查询以近 3 个月为准 | 引用旧闻须注明时间 |
| 招聘、联系方式 | 近 6 个月 | 需注明来源 |

## 6. 打分示例

### 示例 1 —— 3 分

- **查询**：比亚迪法人是谁
- **结果**：给出"比亚迪股份有限公司"的法定代表人姓名，注明数据来源为国家企业信用信息公示系统及查询日期；补充说明公司统一社会信用代码与经营状态"存续"。
- **理由**：实体准确，直接回答，字段准确，有来源和时间，附带必要的识别信息。

### 示例 2 —— 3 分

- **查询**：小米注册资本多少
- **结果**：正确识别为"小米科技有限责任公司"，给出注册资本，单位正确；但未说明数据时间，也未提示"小米集团"为上市主体、两者不同。
- **理由**：核心需求满足，信息准确；未做主体区分说明、未标注数据时间属于不影响使用的小瑕疵，仍给 3 分，但须在备注中注明。

### 示例 3 —— 2 分

- **查询**：长城公司有没有官司
- **结果**：默认按"长城汽车股份有限公司"返回了几条诉讼记录，未提及还有大量其他"长城"字号企业，也未覆盖被执行、失信等维度。
- **理由**：简称歧义未消歧（C3，封顶 2）；风险维度不完整。

### 示例 4 —— 1 分

- **查询**：某某科技（深圳）有限公司的股东有哪些
- **结果**：给出了公司简介和业务介绍，股东部分只写"请登录企业信息公示系统查看"。
- **理由**：相关但未回答核心问题，且信息属于公开可查（C6，封顶 1）。

### 示例 5 —— 0 分

- **查询**：杭州某某贸易有限公司靠谱吗
- **结果**：回答"该公司经营正常、信用良好，可放心合作"，但该企业实际已于去年被吊销营业执照。
- **理由**：关键结论颠倒（V4），可能直接导致错误决策。

### 示例 6 —— 0 分

- **查询**：上海华美医疗器械有限公司
- **结果**：返回的是"广州华美医疗器械有限公司"的工商信息，未做任何提示。
- **理由**：实体错误（V1）。

## 7. 可选：维度量化打分（用于分析）

若项目需要细粒度分析系统问题，可在总分之外，对 7 个维度分别打 0–2 分（0 差 / 1 一般 / 2 好），并计算加权分：

| 维度 | 权重 |
|---|:---:|
| D1 实体准确性 | 25% |
| D3 信息准确性 | 20% |
| D2 意图满足度 | 20% |
| D5 时效性 | 10% |
| D4 完整性 | 10% |
| D6 来源可信度 | 10% |
| D7 表达与可用性 | 5% |

```
加权分 = Σ(维度分 / 2 × 权重) × 3        # 折算到 0–3
最终分 = min(加权分, 封顶值)；命中否决项则为 0
```

> 说明：**最终交付以第 4 节的整体判断分为准**，加权分仅用于定位问题和校验标注一致性。两者相差 ≥ 1 分时，标注员需复核并在备注中说明原因。

## 8. 特殊情况处理

| 情况 | 处理方式 |
|---|---|
| 查询本身有歧义，结果列出多个候选并给出区分信息 | 视为良好处理，可给 3 分 |
| 查询的企业确实不存在 / 查无此企业，系统明确告知并给出相近候选 | 可给 3 分 |
| 查询的企业不存在，系统却编造信息 | 0 分（V2） |
| 用户查询自然人隐私（如股东的身份证号、私人电话） | 系统合理拒答并说明原因，不扣分，按"拒答合理性"给 3 分；如泄露则 0 分（V5） |
| 涉及非公开信息（未上市公司详细财务等），系统说明无法获取并给出可行替代途径 | 不视为 C6，可给 2–3 分 |
| 结果中部分信息无法由标注员核实 | 在备注标记"待核实"，提交质检，不要凭感觉判定对错 |
| 港澳台及境外企业 | 以当地官方登记机构信息为准，同样适用本标准 |
| 结果冗长但正确 | 主要信息在开头或显著位置给出的不扣分；关键答案被淹没的，D2/D7 降档 |

## 9. 标注输出格式

每条样本需填写：

| 字段 | 说明 |
|---|---|
| `query_id` | 查询编号 |
| `query_type` | A–G，可多选 |
| `target_entity` | 标注员判断的目标企业（全称 / 信用代码） |
| `core_need` | 核心需求，一句话 |
| `veto` | 命中的否决项编号，无则留空 |
| `caps` | 命中的封顶规则编号，可多个 |
| `score` | 最终分（0–3） |
| `dim_scores` | 可选，7 维度分 |
| `reason` | 打分理由，**必须**说明扣分点，不少于 15 字 |
| `need_review` | 是否需要质检复核（是 / 否） |

---

## 10. 质量控制

1. **培训与试标**：标注员需先完成 ≥ 50 条试标题，与标准答案的一致率 ≥ 85%（分数相同视为一致）方可上岗。
2. **双人标注**：每条样本至少 2 人独立标注；分差 ≥ 2 分，或一人判否决项另一人未判的，进入仲裁。
3. **一致性指标**：加权 Kappa（quadratic weighted kappa）目标 ≥ 0.7；低于 0.6 时暂停标注，组织对齐。
4. **抽检**：质检员每批抽检 ≥ 10%；抽检错误率 > 10% 的批次整批返工。
5. **案例库维护**：仲裁中出现的典型争议案例沉淀到案例库，标准每季度修订一次，修订记录写入版本号。
